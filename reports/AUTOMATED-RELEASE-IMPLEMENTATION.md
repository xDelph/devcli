### 2. Automated Versioning & Changelog ✅

**Tool**: Release Please (by Google)

**How it works:**
1. You commit to `develop` using conventional commits
2. Release Please creates "Release PR" with:
   - Bumped version in `Cargo.toml`
   - Generated `CHANGELOG.md` entries
3. You merge Release PR
4. Release Please creates git tag automatically
5. Tag triggers release workflow
6. Binaries built + docs synced to public repo

### 3. Conventional Commits ✅

**Format**: `<type>(<scope>): <subject>`

**Types**:
- `feat:` → Minor version bump (0.1.0 → 0.2.0)
- `fix:` → Patch version bump (0.1.0 → 0.1.1)
- `perf:` → Patch version bump
- `feat!:` or `BREAKING CHANGE:` → Major version bump (0.1.0 → 1.0.0)
- `docs:`, `refactor:` → No bump, but in changelog
- `style:`, `test:`, `chore:`, `ci:`, `build:` → No bump, hidden

**Examples**:
```bash
feat(tui): add syntax highlighting
fix(monitor): prevent restart loop
perf(startup): lazy-load configuration
docs: update README installation
```

## Release Workflow

### Old Process (Manual) ❌

1. Manually bump version in `Cargo.toml`
2. Manually write `CHANGELOG.md` entries
3. Manually create git tag: `git tag v0.2.0 && git push --tags`
4. GitHub Actions builds and releases

**Problems:**
- ❌ Tedious manual work
- ❌ Easy to forget steps
- ❌ Inconsistent changelog format
- ❌ Human error in versioning

### New Process (Automated) ✅

1. **Develop**: Make changes with conventional commits
   ```bash
   git commit -m "feat(tui): add dark mode"
   git commit -m "fix(monitor): handle SIGTERM"
   git push origin develop
   ```

2. **Release Please**: Creates Release PR automatically
   - Updates version: `0.1.0` → `0.2.0`
   - Generates changelog entries
   - PR title: `chore(main): release 0.2.0`

3. **Review & Merge**: Merge Release PR when ready
   ```bash
   gh pr merge <PR_NUMBER> --merge
   ```

4. **Automatic Release**:
   - Tag created: `v0.2.0`
   - Workflow triggered
   - Binaries built for all platforms
   - Docs synced to public repo
   - Release published!

**Benefits:**
- ✅ Fully automated versioning
- ✅ Automatic changelog generation
- ✅ Consistent formatting
- ✅ No manual tagging needed
- ✅ Clear release history
- ✅ Faster releases

## Commit Message Quick Reference

```bash
# Features (minor bump: 0.1.0 → 0.2.0)
git commit -m "feat(tui): add syntax highlighting"
git commit -m "feat(api): add metrics endpoint"

# Bug Fixes (patch bump: 0.1.0 → 0.1.1)
git commit -m "fix(monitor): prevent restart loop"
git commit -m "fix(config): handle missing files"

# Performance (patch bump)
git commit -m "perf(startup): lazy-load modules"

# Breaking Changes (major bump: 0.1.0 → 1.0.0)
git commit -m "feat(config)!: migrate to YAML

BREAKING CHANGE: Config now uses YAML format"

# Documentation (no bump)
git commit -m "docs: update README"

# Refactoring (no bump)
git commit -m "refactor(process): simplify spawn logic"

# Other (hidden from changelog)
git commit -m "chore: update dependencies"
git commit -m "test: add integration tests"
git commit -m "ci: improve caching"
```

## Troubleshooting

### Release PR Not Created

**Symptoms**: Pushed to develop but no Release PR

**Causes**:
1. Commits don't use conventional format
2. Only non-releasable commits (chore, style, test)
3. Release Please workflow not enabled

**Fix**:
```bash
# Add a conventional commit
git commit --allow-empty -m "chore: trigger release"
git push
```

### Wrong Version Bump

**Symptoms**: Expected minor, got patch

**Cause**: Using `fix:` instead of `feat:`

**Fix**: Commit type determines bump:
- `fix:` → patch
- `feat:` → minor
- `feat!:` or `BREAKING CHANGE:` → major

### Tag Already Exists

**Symptoms**: Release Please errors about existing tag

**Cause**: Tag exists but release wasn't created

**Fix**:
```bash
# Delete local and remote tag
git tag -d v0.1.0
git push origin :refs/tags/v0.1.0

# Merge Release PR again
```
